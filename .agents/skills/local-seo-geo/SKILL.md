# Reusable local SEO + GEO content workflow

This is a portable skill. Read the target project's `AGENTS.md` and business context first; never assume every client shares GyanArt's location, service scope, or site structure.

1. Confirm approved business name, services, physical/service-area location, public contact details, customers and primary lead action. Identify the target page's one dominant buyer intent from the approved keyword-to-page map.
2. Review the live page and source. Check an accurate, helpful title/H1, readable first paragraph, substantive service/process details, transparent limits, meaningful FAQ answers (without spam markup), internal links, images/alt text, and an obvious enquiry route.
3. Use firsthand, verifiable facts. Do not invent reviews, results, guarantees, awards, prices, client permissions, photographs, business categories, addresses or service areas.
4. For every case study, label actual work vs. demo/concept/proposal; verify claims and permissions before publishing.
5. Review localization only where that project uses multiple languages: equivalent page purpose, proper language tags, reciprocal hreflang, canonical behavior, and functional navigation.
6. Verify public business identity (including GBP if available) before recommending schema changes. Markup must match the visible real business and Google's current eligibility criteria; generic FAQ/HowTo schema is not a shortcut to rich results.
7. Prioritize buyer value over repetition: plain language, distinctive examples, factual answers to questions buyers ask, and links to verified supporting information.
8. Output: existing URL -> problem for visitors -> proposed precise edit -> evidence -> measurable acceptance criterion. Propose changes in a reviewable PR and do not promise rankings or AI citations.

Use free inspection and official testing tools first. Do not require paid SEO subscriptions, third-party APIs or automatic publishing.
